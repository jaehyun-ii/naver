# AIReg-KR 스위트 트랙별 프롬프트 정리

`prompts.py` 기준 (2026-07-22, suite_v3 배치 세대). 산출물의 `_gen.prompt`
필드(`SPEC_QA/v4` 형식)로 어느 프롬프트 세대가 생성했는지 추적된다.

## 파이프라인에서의 위치

```
라우팅(router) → 트랙별 생성 프롬프트 → 정적 게이트(인용 스팬·범위·참조 정합)
             → 블라인드 검증(SUITE_VERIFY) → [REJECT 시] 답변 국소 수리(ANSWER_REPAIR)
                                            또는 피드백 재생성(REGEN_FEEDBACK, 최대 2회)
```

설계 원칙: **LLM은 시나리오·서술만 담당**하고, 판정 구조는 선판정 필드
(premise/branch_check)로 강제하며, 수치·인용은 프로그램이 검증·조립한다
(unit_convert의 문제·정답 조립, quote snapping, 스팬 게이트 등).

## 공통 규칙 (LANG_RULE — 전 프롬프트 부착)

- 모든 생성 텍스트는 한국어 전용(한자·일본어·영어 문장 혼입 금지, 고유명사
  괄호 병기만 허용).
- 인용(quote·evidence) 필드는 예외: 원문에서 **한 글자도 바꾸지 말고** 복사
  (원문이 영어면 영어 그대로).
- 인용은 원문의 **연속된 한 구간**만 — 떨어진 문장을 `...`/`…`로 이어 붙이기
  금지 (2026-07-22 강화).
- 표·수식 인용도 원문 표기 그대로 — 셀 값 재조립, ∑/LaTeX 등 다른 기호 체계로
  변환 금지 (2026-07-22 강화).

## 트랙별 생성 프롬프트

| 트랙 | 프롬프트 (버전) | 과제 | 핵심 출력 필드 |
|---|---|---|---|
| spec | SPEC_QA (v4) | 조항+Rule Card 기반 실무형 QA 최대 n개 | `qa[]`: question, answer, evidence_quote |
| applicability | APPLICABILITY (v13) | 적용/미적용 시나리오 2개 | premise_clauses/facts, scenario, label, reason, evidence_quote |
| crossref | CROSSREF_QA (v6) | 본 조항+참조 조항 결합 필수 QA 1개 | question, answer, main_quote, ref_quote |
| def_link | DEF_LINK_QA (v5) | 정의 조항+본문 조항 결합 QA 1개 | question, answer, definition_quote, definition_ref_quote, requirement_quote |
| precedence | PRECEDENCE_QA (v9) | 일반 vs 특별 규정 우선관계 판정 | scenario, branch_check(relation), answer, special/general_quote |
| table_lookup | TABLE_LOOKUP_QA (v4) | 표의 특정 행 선택 필수 문제 | row/column_selector, answer_value, evidence_quote |
| hierarchy | HIERARCHY_QA (v11) | 항>호>목 상위 전제 내 하위 항목 적용 판정 | premise_upper/leaf/alignment, scenario, applies, answer, evidence_quote |
| unit_convert | UNIT_EXCERPT (v5) | 설계값 포함 제출문서 발췌만 생성 | excerpt_title, excerpt |

### spec — SPEC_QA
- 답이 제공된 조항 원문만으로 유일하게 결정(복수 해석·모호 범위 금지),
  외부 지식(타 조항·타 선급·IMO) 요구 금지.
- **한정어 보존**: "연속" 갑판 보, "제3급" 압력용기 등 대상 한정 수식어 탈락 금지
  (탈락 시 적용 범위 확대 왜곡).
- **수식어 창작 금지**: 원문에 없는 범위 표현("각 선박의" 등) 덧붙이기 금지.
- 영문 규범 술어 의미 보존 예시 포함("can only be fulfilled when X" 오역 방지).

### applicability — APPLICABILITY
- **적용 여부만 판정, 이행(준수)과 분리** — 요건 미이행은 '적용되며 부적합'이지
  미적용이 아님. 미적용은 적용 대상·범위(선종·규모·용도) 밖일 때만.
- 조항 전체 기준 판정: 일부 항·호만 비적용이면 조항 전체로는 applicable.
- **선판정 구조**: scenario 작성 전에 premise_clauses(관련 호·단서와 조건)와
  premise_facts(평가용 시나리오 사실)를 먼저 쓰고, reason은 각 호를 순서대로
  평가(①②③… 형식 예시 제공).
- 라벨 쏠림 방지는 코드에서: 조 해시로 applicable/미적용 시나리오를 교대 선택.
- 시나리오 용어는 조항 원문 용어 그대로(유사어 금지), 결론 문장 서술 금지.

### crossref — CROSSREF_QA
- 본 조항만으로 답할 수 있는 질문은 무효 — 참조 조항 내용이 답에 필수.
- **참조 내용 전개 필수**: 참조 조·항 번호만 반복하는 답 무효(번호가 규정하는
  요건·조건·효과를 풀어 쓸 것).
- 원문 밖 세부 금지: 두 조문에 문자 그대로 존재하는 번호·수치만 사용,
  "201.1항"식 조·항 합성 표기 금지, 비교 방향(이상/이하/초과/미만) 재대조.
- 수식 기호 역할 단일성(같은 기호에 두 정의 금지), 특별요건 우선(일반 선택지
  확장 나열 금지), 질문 전제는 본 조항 적용 범위와 무모순.

### def_link — DEF_LINK_QA
- 질문에 정의 내용을 풀어 쓰지 않되 정답 도출엔 정의가 필수 — 상황은 용어 대신
  정의에 해당하는 **구체 사실**로 기술(수험자가 사실→용어 매핑 수행).
- answer는 2단계 필수: (1) 상황 사실이 왜 해당 용어인지(정의 적용) (2) 본문
  요건 적용 결론.
- **참조로 열린 정의**: 정의가 다른 조항을 참조하면(예: "402.1에 따른 탱크")
  그 조항이 제공된 경우에만 사용하고 3-근거(정의→참조 요건→시나리오)로 완결.
- 조건문·재량 표현("~한 경우", "고려할 수 있다")을 절대 요건으로 변환 금지.
- 억지 결합 금지: 판정과 무관한 대상을 용어에 끼워 맞추는 구성 무효.

### precedence — PRECEDENCE_QA
- 일반 원칙과 특별 조항의 적용 조건을 **동시에 충족**하는 시나리오 설정.
- **선판정 구조(branch_check)**: 답 작성 전 양쪽 적용 조건 나열 + matched 판정 +
  관계를 원문 문구(explicit_marker) 기반 7분류:
  `OVERRIDES`(적용하지 아니한다) / `SUBSTITUTES`(대신 적용) / `EXCEPTION`(다만) /
  `LIMITED_EXCEPTION`(일부 범위만) / `DISCRETIONARY`(고려·인정할 수 있다) /
  `ADDITIONAL`(추가 요건) / `UNCLEAR`.
- **결론은 relation을 따름**: 배제·대체 결론은 OVERRIDES/SUBSTITUTES + 명시
  문구가 있을 때만. DISCRETIONARY는 확정 결론 금지("승인 전제 대안 인정 가능"으로
  서술). 배제 범위를 특별 규정이 명시한 범위 밖으로 확대 금지. 단서의 별도
  효과(면제·완화)는 그 효과 그대로 결론.
- 질문이 대비시킨 두 규정 = 답이 비교하는 두 규정(도중 교체 무효). 표 행·비고는
  대상 속성 전부 일치 시에만 연결.

### table_lookup — TABLE_LOOKUP_QA
- 질문 조건은 표의 정확히 **한 행**(필요 시 한 열)에만 해당 — 두 행 걸침·표에
  없는 조건 금지.
- **구간 경계 보존**: "넘고/이하" = 초과~이하(하한 미포함·상한 포함). 이상/미만으로
  바꾸면 경계값에서 다른 행이 선택됨 — 원문 포함 관계 그대로 표현.
- 셀 내 조건("필요시", "~인 경우") 보존 — 무조건 요구로 변환 금지.
- row/column_selector·answer_value는 표 원문 표기 그대로, 표에 없는 기호·헤더
  창작 금지. answer는 행 선택 이유 + 읽은 기준값 의미 서술.

### hierarchy — HIERARCHY_QA (규칙 최다 트랙)
- 권장 형태: 최하위 항목 문면에는 부합하지만 상위 항·호 전제에는 해당하지 않는
  상황(또는 반대) → 적용 여부 판정.
- **선판정 구조**: premise_upper(상위 전제와 성격) → premise_leaf(하위 조건) →
  premise_alignment(사실별 충족) 순서로 먼저 작성, answer는 그 순서로 결론.
- **상위 항 성격 판별이 핵심**: ⓐ 범위 정의("~인 구획에는")면 범위 밖은 미적용,
  ⓑ 수행 의무("시험을 받아야 한다")면 미이행은 위반이지 미적용 아님.
- 의무 위반 ≠ 미적용(요구 속성을 적용 전제로 해석 금지), 절차 서술 문장의 상태는
  준수 내용이지 적용 전제가 아님, 병행 조항을 배타 분기로 해석 금지.
- 정의 목록형 하위 목((가)(나)…)은 "이 정의에 해당하는가"형 질문으로.
- 시나리오 사실 무모순 + 확정 사실 취급(answer에서 "명시되지 않았다" 유보 무효).

### unit_convert — UNIT_EXCERPT
- LLM 역할 최소화: "{fact_value} {fact_unit}" 표기를 **그대로** 포함한 제출문서
  발췌(2~4문장)만 생성 — 환산·반올림·수치 추가 금지, 다른 물리량·설비로 치환 금지.
- 단위 환산 문제·정답·판정은 프로그램이 결정적으로 조립(수치 오류 원천 차단).
- 발췌 공통 규칙(_EXCERPT_RULES): 기준값 노출 금지 등.

## 검증 프롬프트 — SUITE_VERIFY (v6)

블라인드 검수(생성 과정 비공개, 원문+QA만 제공). 정적 인용 게이트가 '그대로
복사했는가'를 보장하는 것과 달리, **원문 의미와의 정합**을 본다. 기준 7개
(하나라도 위반 시 REJECT):

1. **전제 일치** — QA가 원문에 관해 서술한 내용(요약·인용·항호 경로·수치)이
   원문과 일치. 단, 시나리오가 적용 범위 밖인 것 자체는 위반 아님(의도된 출제).
2. **유일 도출** — 원문만으로 답이 유일하게 도출(외부지식·추정 금지).
3. **용어 대응** — 원문이 용어 A에 규정한 내용을 유사 용어 B에 대한 것처럼
   서술하면 REJECT(주 검출 대상, `term_mismatch` 플래그).
4. **수치·단위** — 수치·단위·비교 경계가 원문과 일치.
5. **시나리오 내부 일관성** — 상반된 사실 병존 금지.
6. **응답 완전성** — 질문의 각 항목에 실질 내용으로 답할 것(번호 인용으로 내용
   답변 대체 금지).
7. **판정 전제 충분성** — 예외·승인 경로 성립 여부에 따라 결론이 갈리면
   시나리오에 그 전제가 명시돼야 함.

조건부 감시 블록: `NUM_WATCH`(원문에 없는 수치 → 환산인지 날조인지 구분),
`XREF_WATCH`(특별요건을 참조 조항 일반 선택지로 완화하는 서술 검출),
`TERM_WATCH`(유사 용어 쌍의 원문 줄 대조 절차), `JUDGMENT_GUIDE`(판정형 문제에서
'대상이 다르다'는 이유만의 REJECT 방지).

출력: `{verdict, issues[], term_mismatch, severity}`.

## 보조 프롬프트

- **ANSWER_REPAIR (v1)** — 검증 REJECT 사유가 전부 답변측(결론·완전성·서술)일 때
  질문·시나리오를 보존하고 답변만 교정 후 재검증(전면 재생성의 '새 시나리오 →
  새 결함' 진동 회피). 프로그램 조립 트랙(unit·table)은 제외.
- **REGEN_FEEDBACK** — 정적 게이트·검증 사유를 피드백으로 붙여 재생성(최대 2회).
  EVIDENCE류(원문 자체에 근거 부족)는 재생성 불가로 즉시 REVIEW 종료.
